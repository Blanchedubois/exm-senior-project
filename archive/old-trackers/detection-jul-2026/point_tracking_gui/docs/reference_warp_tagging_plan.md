# Implementation Plan — Reference-Warp Tagging & Pairing

**The idea (yours).** Build the tag map **once, on the reference STL** — every printed point gets a
unique, grid-relative tag. Then, per expansion image, **warp the tagged reference onto the image's
own grid** (align to its grid lines / boxes) and assign each detected image point the tag of the
**nearest warped reference point**. Pairing across expansions is then automatic: two images that
were each tagged from the same reference share tags on the same physical points.

This inverts the previous approach (which computed a tag independently on each image and hoped they
agreed). Here the reference is the single source of truth and the warp carries the tags in — so the
brittle per-image dot-index quantisation disappears, and even **unreadable glyphs get tagged by
position**.

---

## 0. Ground truth measured from the STL (`base_design_for_nanoscribe_2026_01_14.stl`)

750×750 µm, 5×5 boxes = **150 µm/box**, features 2 µm tall. Feature inventory (parsed directly):

| Category | Count | Geometry | Belongs to |
|---|---|---|---|
| **Intersection dots** | 36 | one at each grid crossing, exact **(150·i, 150·j)**, i,j∈0..5 | a grid **node** |
| **Dashes** | 600 | on the 6 V + 6 H grid lines, **10 per box-edge at 12 + 14·k µm** | a grid **line** |
| **Interior dots** | 6400 | global **8.000 µm lattice, phase 5 µm** (not box-aligned) | a **box** |
| **Numbers** | ~250 | 3×3 slots: box number at 4 corners + centre; 2 digits split ±~7 µm | a **box** |
| **Letters** | ~100 | A/B/C/D at the 4 edge mid-slots | a **box** |

Box numbering: `N = col*5 + row + 1`, column-major (box 1 bottom-left → 5 top-left → 25 top-right).

## 1. Part A — The canonical reference tag map (built once from the STL)

A pure-data artifact `reference_tags.json`: a list of records, each `{tag, category, x_um, y_um,
[meta]}`. Generated by enumerating the design (not by detecting), so it is exact.

### Tag schemes (unique, grid-relative, human-readable)

**(1) Grid nodes — intersection dots** → warp control points
```
node|{i}_{j}            at (150·i, 150·j)          i,j ∈ 0..5   (36 tags)
```

**(2) Grid-line features — dashes**
```
dash|V{i}|{m}           on vertical line x=150·i,  m = 0..49 up the line   (6×50)
dash|H{j}|{m}           on horizontal line y=150·j, m = 0..49 across       (6×50)
   # m = 10·span + k : span 0..4 is which box-edge, k 0..9 is the dash in it
```

**(3) Box-interior features**
```
dot|B{N}|{di}_{dj}      interior lattice dot, (di,dj) = its lattice index RELATIVE to box N's corner
num|B{N}|{slot}|{tens|units}   slot ∈ {corner00,corner02,corner20,corner22,center}
let|B{N}|{slot}         slot ∈ {A,B,C,D}
```
Dots and glyphs are tagged **relative to their box** (your "unique to each number"); dashes relative
to their **line**; corner dots relative to their **node**. Every tag also stores its exact design
(x,y) in µm — that is what gets warped.

*Deliverable A:* `reference/reference_tags.json` + a `build_reference_tags.py` that regenerates it
from the STL, and a montage overlay (tags drawn on the STL render) to eyeball correctness.

## 2. Part B — The new pipeline stage: **Warp reference → image, then tag by proximity**

Runs after the existing detection + registration (which already gives the image's dots, dashes,
glyphs, box grid and **box numbers**). New stage does four things:

### B1. Establish grid correspondence (reference node ↔ image node)
The registration tells us which boxes (hence which grid nodes `(i,j)`) are in view and their numbers.
Image-side node positions come from **one of** (in priority order):
- **detected intersection dots** (category 3) — the design's built-in registration marks, matched to
  `node|i_j` by the box grid; the cleanest control points, *or*
- the **box-grid fit corners** (from dashes / dot-lattice fit) where a corner dot isn't detected.

Result: a set of correspondences `node|i_j (design µm) → (px)` for the visible grid.

### B2. Fit the warp (reference µm → image px)
Candidate models (workshop item Q1):
- **Global homography** — simplest; good for mild, near-uniform expansion.
- **Per-box homography** — each box's 4 corner nodes → image; captures box-to-box strain; needs a
  box's 4 corners (falls back to neighbours for edge/partial boxes).
- **Thin-plate spline (TPS)** through all matched nodes — smooth, non-uniform, robust to a missing
  corner. *Recommended default.*

### B3. Warp every reference tag point into image space
Push all ~7 400 reference points through the fitted warp → each tag now has an **expected pixel
position** in this image. (For partial views, only tags whose box/line/node is in view.)

### B4. Assign tags by nearest detected feature (per category, one-to-one)
For each warped reference point, find the nearest **detected feature of the same category** within a
tolerance (≈ 0.4 × local dot pitch, scaled by the warp's local Jacobian):
- reference dots → detected dots, dashes → dashes, node dots → intersection dots.
- glyph slots → detected glyph blobs **by position** — the tag comes from *where* the slot is, not
  from reading the digit, so unreadable high-expansion glyphs still get tagged.
Greedy nearest, one detection per tag (**no double counting**). Unmatched reference tag = "absent
here"; unmatched detection = spurious/untagged.

*Deliverable B:* a `TaggedFeatures` table (detected point → reference tag, or None) + an overlay that
draws the warped reference grid and the tag assignments over the image.

---

## 3. Part C — Pairing across expansions (now trivial)
Every image is tagged against the **same** reference, so a physical point has the same tag in each
image it appears in. Pairing = **inner join on tag**; the wide pairing CSV is one row per reference
tag with per-expansion `(x_px, y_px, present)`. Strain consumes the joined pixel positions exactly as
now. N expansions join in one pass.

---

## 4. Why this is better than per-image indexing
- **No dot-index quantisation.** Dots are matched to *warped expected positions*, not re-quantised to
  a lattice per image — the failure mode that mis-tagged dots across tilted frames is gone.
- **Glyph tags don't need OCR.** Position from the warp is enough — fixes high-expansion glyphs.
- **Non-uniform strain handled by construction** (per-box / TPS warp).
- **One canonical definition** of every tag; the reference doubles as the expected-position model.
- **Registration still seeds it**, but the warp then predicts *everything*, so a coarse box
  correspondence (even one anchored box + the node lattice) can region-grow to a full tagging.

  dots / 205 number-digits / 100 letters. Overlay on the STL render confirms correct placement and
  box numbering; box-13 zoom shows corner nodes, slot digits, letters, lattice dots, boundary dashes.
- **P2 — Warp fit (reference → image). ✅ DONE & VERIFIED.** `refwarp/detect.py` (detection wrapper)
  + `refwarp/warp.py`. **Revised control-point finding:** the corner *intersection dots* are NOT
  reliably detected on real prints (snap residual ~1 dot-pitch → wrong dots), so instead the warp is
  driven by the **dense interior dot lattice**: seed a global affine from the box-grid fit +
  registration, then ICP-refine a homography against the detected dots. *Verified:* 1.5× median
  **2.9 px** (93% of detected dots matched, 2304 pairs), 2.0× **4.4 px** (94%) — both ≈0.1 dot pitch.
- **P3 — Tag-by-proximity. ✅ DONE & VERIFIED.** `refwarp/tagmatch.py` warps every reference tag point
  and assigns each detected feature (dots→dot/node, dashes→dash, glyph blobs→num/let) the nearest
  warped tag, one-to-one. *Verified 1.5×∩2.0×:* **1654 shared tags** (1458 dot / 142 dash / 54 num) —
  beats the old lattice approach's 1116; **0 duplicates**; per-box dot residual **5.9 px, 0% >15 px**
  (2× pitch ≈41) → every shared tag is the same physical dot. Numbers tag by position (warp 10 px).
  KNOWN GAP: letters aren't picked up by the existing `detect_glyph_blobs` (pre-existing detection
  limitation) so `let|` tags are sparse — irrelevant to pairing (dots/dashes/numbers carry it).
- **P4 — TPS + harder expansions. ✅ DONE & VERIFIED.** `warp.fit_warp` adds a thin-plate spline
  refinement over the ICP homography (2.5× warp residual 7.0 → **0.1 px**). `refwarp/coreg.py`
  auto-registers 3.0×–4.2× (unreadable digits) by aligning their mis-numbered dot pattern to a
  correctly-registered LOWER frame and transferring box numbers; `refwarp/session.py` chains the

  reference is box-periodic and can't fix the offset; (b) validate by **shared tags** with the good
  frames, not warp residual (a mis-numbered fit still has low residual on the periodic lattice); and
  each hard frame aligns to *whichever* lower frame overlaps it (they image different regions).
  *Verified full 1.5×–4.2×:* all 6 accepted, 2798 distinct tags, **1831 pairable** (≥2 frames); shared

## 7. Decisions (locked in with the user)
1. **Warp model = thin-plate spline (TPS)** through all matched grid nodes — smooth, non-uniform,
   tolerant of a missing corner. (Global homography kept as a cheap seed/fallback for TPS.)
2. **Control points = dense interior dot lattice** (REVISED in P2). The corner intersection dots turned
   out not to be reliably detected on real prints, so the warp is fit by ICP against the ~2500 detected
   interior dots (seeded by the box-grid affine) — far more control points and ~0.1-pitch residual. The
   36 `node|i_j` tags are still exported (they warp along with everything) but no longer drive the fit.
3. **Glyph tags by warped position** — a slot's tag comes from where it sits under the warp, not from
   reading the digit; unreadable high-expansion glyphs still tag. (Reading still used to seed box
   numbers only.)
4. **High-expansion seed = reuse the existing machinery** — read box numbers where possible; else
   auto-align to a correctly-registered lower expansion (chirality-validated) or a one-click manual
   box anchor; the TPS warp then propagates from that seed.
5. **Interior dot tag = box-relative** `dot|B{N}|{di}_{dj}` (matches "unique to each number").
6. **Warp direction = reference → image**, match detected features in pixel space.
7. **Location = this `point_tracking_gui`** as a new stage; port to the strain app afterward.

## 8. Open items (implementation detail, decide during build)
- **TPS seeding:** fit a global homography from the matched nodes first, then TPS as the residual
  warp — keeps the spline well-conditioned when only a few nodes are visible (high expansion).
- **Matching tolerance:** scale the per-category nearest-neighbour gate by the warp's *local* Jacobian
  (so it grows with local expansion) rather than a fixed pixel radius.
- **Corner-dot detection:** the intersection dots are small; confirm the existing dot detector finds
  them, or add a targeted detector near predicted node positions after a first coarse warp.
